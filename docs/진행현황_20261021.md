## 4. 기획과 달라진 점·결정

- **대화 모델 미사용:** 기획서는 LLM이 안내 문구를 쓰는 구조였으나, 지금 안내 문구는 전부 고정 문구. AI는 사진 분석 한 곳에서만 쓰임 → 제출 평가에서 약해 보일 수 있음.
- **React 대신 바닐라 JS:** 빌드 단계를 없애 속도를 우선함.
- **현장 모드(허브) 추가:** 급박한 현장에서는 핵심 3장만 하고 나머지는 나중에 이어서. 기획서에 없던 변경.
- **손상 사진 판정:** 모델이 근접 손상 사진을 "차량 전체"로 분류해, 장면 유형 대신 "손상이 보이는지"로 판정하도록 변경(실모델로 통과 확인).
- **위치·현장 음성 기록 제외:** 법적·개인정보 부담과 일정 때문.
- **App Runner 사용 불가:** 2026-04-30부터 신규 고객 접수 중단. AWS는 Lightsail 컨테이너 서비스를 우선 검토.

## 5. 아직 검증하지 못한 것

- 실제 폰에서의 동작(카메라·음성·레이아웃)
- 번호판이 읽히는 사진에서의 "번호판 통과" 경로(테스트 사진에 없음)
- Dockerfile 빌드(Docker가 꺼져 있었음)
- 사진 40~60장 기준 장면 분류·흐림 판단 정확도
- 위의 개선(현장 모드 등)이 실제로 시간을 줄이는지

## 6. 남은 일 (우선순위)

1. **배포(HTTPS 데모 URL)와 폰 실기기 확인** — 제출 요건이고 막히면 대안이 없음
2. **AI 역할 확대:** 자유 발화 이해, 진술 구조화, 번호판·서류 읽기(+확인 절차). 안전 원칙(규칙 우선, 금지 검사, 사용자 확인)은 유지
3. **앱 안 카메라**(카메라 앱 전환 제거) + 비동기 판정 — HTTPS 필요
4. **평가:** 사진 데이터 확보, 정확도 측정, 범용 AI 비교, 실패 사례 1건 이상 공개
5. **제출물:** 저장소 공개 + LICENSE, 영어 README·설명문, 3분 미만 영상, Nebius/NVIDIA 피드백
6. 선택: STT, 접속 제한(공개 URL 남용 방지), 세션 삭제 시한

## 7. 다시 시작할 때

```bash
uv sync                  # 처음 한 번
uv run scenepilot        # http://localhost:8000
uv run pytest -q
uv run python eval/run_vision_eval.py     # 실제 모델로 eval/photos 사진 4장 시험
```
- 키: 프로젝트 루트 `.env` 의 `NEBIUS_API_KEY` (`.env` 는 git 에 올라가지 않음). 이전에 채팅에 노출된 키는 폐기하고 새 키 사용.
- 코드 위치: `src/scenepilot/` (`session.py` 상태기계, `emergency.py`, `guard.py`, `checklist.py`, `vision.py`, `app.py`, `static/` UI)
